# Task files

| ไฟล์ | เฟส | สรุปสั้น |
|---|---|---|
| [P0-setup.md](./P0-setup.md) | ตั้งต้นโปรเจกต์ | Next.js + Supabase + CI + design token |
| [P1-data-public.md](./P1-data-public.md) | ข้อมูล + หน้าอ่านอย่างเดียว | schema + RLS + หน้าแรก/ค้นหา/รายละเอียด |
| [P2-seo.md](./P2-seo.md) | SEO | metadata, JSON-LD, sitemap, landing page รายอำเภอ |
| [P3-map.md](./P3-map.md) | แผนที่ | Longdo Map v3 แทน tile renderer เดิม |
| [P4-forms.md](./P4-forms.md) | ฟอร์มสาธารณะ | lead / ฝากขาย / ต้องการซื้อ + กันบอท + แจ้งเตือน |
| [P5-admin.md](./P5-admin.md) | หลังบ้าน | Auth จริง + คิวตรวจ + อนุมัติ + CRM |
| [P6-launch.md](./P6-launch.md) | เตรียมเปิดจริง | PDPA, retention, performance, เนื้อหา |

## โครงของแต่ละไฟล์

- **เป้าหมาย** — เฟสนี้จบแล้วได้อะไร
- **ขอบเขต** — อะไรอยู่ใน / อะไรไม่อยู่ (กันงานบาน)
- **Checklist** — รายการย่อยพร้อมรหัส ติ๊กได้
- **เกณฑ์ว่าเสร็จ** — ตรวจยังไงถึงเรียกว่าจบ ไม่ใช่ "รู้สึกว่าเสร็จ"
- **ไฟล์ที่จะแตะ** — เดาโครงไฟล์ไว้ล่วงหน้า
- **ข้อควรระวัง** — กับดักที่เจอจาก prototype

## กติกา

1. ทำทีละเฟสตามลำดับ ยกเว้น P2 / P3 / P4 ที่ขนานกันได้หลัง P1 จบ
2. ปิด task แล้วต้องอัปเดต `PROGRESS.md` ด้วยเสมอ (มีวิธีเขียนไว้ท้ายไฟล์นั้น)
3. commit message อ้างรหัส task เช่น `P1-04: add RLS policies for properties`
4. เจอเรื่องที่ต้องตัดสินใจ → ไปเพิ่มในตาราง "เรื่องที่ติดอยู่" ของ `PROGRESS.md` ทันที
5. ถ้าพบว่าแผนใน `PLAN.md` ผิด → แก้ `PLAN.md` ด้วย อย่าปล่อยให้เอกสารกับโค้ดเล่าคนละเรื่อง
