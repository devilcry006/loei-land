## เป้าหมาย

แอดมินล็อกอินด้วยบัญชีจริง ตรวจทรัพย์ที่รอคิว อนุมัติแล้วขึ้นเว็บทันที และจัดการ lead ตามสถานะ CRM ได้

> **แทนที่ของเดิมทั้งหมด:** prototype ใช้ PIN `2468` ฝังใน JS ฝั่ง client (`index.html:1389`) ซึ่งใครกด View Source ก็เห็น — ไม่ใช่ระบบล็อกอิน

## ขอบเขต

**อยู่ในเฟสนี้:** auth, คิวตรวจ, อนุมัติ/ปฏิเสธ, อัปโหลดรูป, CRM board, export CSV
**ไม่อยู่ในเฟสนี้:** dashboard สถิติ, ระบบมอบหมายงานหลายคน, ประวัติการติดต่อแบบละเอียด — ยกไปหลัง launch

## เกณฑ์ว่า "เสร็จ"

- เข้า `/admin` โดยไม่ล็อกอิน → เด้งไปหน้า login (ทดสอบทั้งผ่าน browser และยิง Server Action ตรง)
- ส่งฟอร์มฝากขาย → เห็นในคิว → กดอนุมัติ → เปิดหน้าเว็บสาธารณะแล้วเห็นทรัพย์ทันที
- อนุมัติแล้วเทียบ `exact_lat` กับ `zone_lat` ต้อง**ต่างกัน** และห่างกันไม่เกิน 1 กม.
- ดู page source หน้าทรัพย์สาธารณะ → **ไม่มี** ชื่อ/เบอร์เจ้าของ, เลขโฉนด, พิกัดจริง
- เปลี่ยนสถานะ CRM แล้วมีแถวเพิ่มใน `crm_events` พร้อมชื่อคนทำ
- export CSV แล้วเปิดใน Excel ภาษาไทยไม่เพี้ยน (ต้องมี BOM)

## ข้อควรระวัง

- **การเบลอพิกัดต้องทำฝั่ง server เท่านั้น** ถ้าทำฝั่ง client แปลว่าพิกัดจริงถูกส่งมาถึง browser แล้ว = หลุดไปแล้ว
- การสุ่มเบลอควรสุ่มครั้งเดียวแล้วเก็บผลไว้ ถ้าสุ่มใหม่ทุกครั้งที่โหลด หมุดจะขยับไปมาและคนเอาไปเฉลี่ยหาจุดจริงได้
- export CSV ต้องมี BOM (`\uFEFF`) นำหน้า ไม่งั้น Excel เปิดภาษาไทยเป็นตัวยึกยือ
- prototype ใช้ index ของ array เป็นตัวอ้างอิงรายการ (`approveSubmission(index)`) — ใช้ไม่ได้กับ DB จริง ต้องใช้ UUID
